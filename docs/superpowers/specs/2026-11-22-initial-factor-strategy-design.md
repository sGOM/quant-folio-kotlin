# 초기 팩터 리밸런싱 전략 수립 — 설계

## 의도

최종 목표는 **스스로 매수·매도하는 알고리즘 + 시스템**이다. 실행 시스템(`engine`: 러너·주문·체결·리컨실·리스크·halt·live_gate)은
이미 있으므로 비어 있는 것은 "무엇을 사고팔지" — 전략이다. 사용자가 고른 운영 형태는 **B: 고정 규칙 자동매매 + 정기 재검토**
(뉴스·성과를 보고 규칙 변경을 *제안*, 반영은 사람이 결정). 이 문서는 그중 **① 초기 전략**만 다룬다.
② 정기 재검토는 ①이 모의투자에 올라간 뒤 별도로 설계한다.

자금 계획: 모의투자로 검증 → 적당하면 실전 수천만 원.

## 목표 / 비목표 / 반목표

- **목표:** 근거(가설)가 글로 남아 있고, 백테스트·모의투자로 검증된 리밸런싱 전략 config 하나를 모의투자에 올린다.
  가설 문서는 ②가 그대로 재평가할 수 있는 형식이어야 한다.
- **비목표:** 뉴스를 실시간 매매 신호로 쓰기(과거 뉴스가 60일치뿐이라 검증 불가), 새 팩터 코드 작성(기존 8개 팩터로 한정 —
  조사에서 필요한 팩터가 나오면 기록만 한다), 실전 전환 실행.
- **반목표:** 백테스트에서만 좋은 전략(시행을 반복해 고른 운), 결과를 보고 가설을 고쳐 쓰기, 전략 23 기동,
  사용자 확인 없는 주문.

## 제약

- 실행 가능한 전략은 `rebalance` config 다(`StrategySchemas`). 팩터: momentum·value·lowvol·quality·growth·flow·residual_momentum·pead.
  PIT 유니버스 소스: `KOSPI200`·`KOSPI100`·`KRX300`(KOSDAQ150 없음). 국면 필터·risk_layer·panic_overlay 사용 가능.
- DB 는 캐시다. 백테스트가 부족분을 네이버 일봉·KRX MDC·OpenDART 에서 받아 채운다(`OhlcvLoader.ensureCoverage`, `StoreCache`).
  첫 실행은 느리고 KRX 로그인을 쓴다 — KRX 계정 차단 이력이 있으니 백테스트를 묶어서 돌리고 반복 재시도하지 않는다.
- 데이터 시작점: 일봉 2017-06~. residual_momentum(36개월 회귀)·pead(8분기)는 점수가 나오는 시점이 그만큼 늦다 — 구간 설계에 반영.
- **공개 저장소.** 실데이터 백테스트 수치·최종 가중치·리서치 노트는 커밋하지 않는다(`quant.md` 2층 규칙과 같은 이유 + 전략 비공개).
- 미래참조: 리서치 단계에도 적용한다. 과거 뉴스를 읽고 고르면 결과를 아는 채로 고르는 것이다.

## 접근법

| 안 | 내용 | 판단 |
|---|---|---|
| **1. 팩터 리밸런싱** | PIT 대형주 유니버스, 월간 15~20종목, 팩터 가중 점수 선정 | **채택.** 분산·저회전, 가설→가중치 문서가 ② 재검토와 맞물림. 단점: 모의 판단에 최소 3개월 |

## 진행 단계

### 1. 리서치 → 가설 (백테스트 전에 확정)

조사 대상:
- 국내 팩터 실증(논문·증권사 퀀트 리포트): KRX 에서 어떤 팩터가 언제 통했고 언제 무너졌나.
- 제도·구조 변화: 밸류업 프로그램, 공매도 재개, 외국인 수급, 거래세율 변화 등 — **오늘 알려진 사실로서** 앞으로의 근거에 쓴다.
- DB 최근 뉴스(`news_articles`, 2026-09~)와 웹 검색: 현재 시장 국면 판단용.

산출물: 가설 2~3개. 각 가설은 *주장 / 근거(출처) / 어떤 팩터·설정으로 옮기는가 / 무엇이 관측되면 틀린 것인가* 를 갖는다.
**가설과 시행 계획은 백테스트 결과를 보기 전에 파일로 확정**하고, 이후 수정은 날짜와 사유를 덧붙여 추가만 한다.

### 2. 번역 → config

가설마다 기본 config 1개 + 변형 최대 4개(시행 총량 ≤ 15회). 공통값(빌더 결정, 근거와 함께 기록):
`universe_rule.source` KOSPI200 또는 KRX300, `top_n` 15~20, `cadence` monthly, `capital` 실전 계획 금액,
`fill_mode` next_close, `fees`·`tax` 는 조사 단계에서 확인한 현행 값, `slippage_bps` 기본 이상.

### 3. 검증 (백테스트)

- 구간: 학습 2017-06~2022-12 / 확인 2023-01~최근 완결월. 확인 구간은 후보당 **한 번만** 본다.
- **실행 방법(사용자 결정):** 사용자가 Chrome 에서 로그인해 두면 Claude in Chrome 으로 그 페이지에서 전략 생성·
  `POST /api/strategies/{id}/backtest` 를 호출한다. 새 코드 없음. 로그인 시도(비밀번호 입력)는 하지 않는다 — 10회 실패면 잠김.
- 모든 시행은 `backtests` 테이블에 남겨 `/api/backtests/{id}/dsr` 의 시행 수에 잡히게 한다.
  DSR 은 `같은 strategy_id + 같은 기간 + 같은 universe_fingerprint` 만 시행으로 세므로, **전 시행을 전략 하나에서 config 를
  바꿔 가며** 돌리고 유니버스 소스는 하나로 고정한다(사용자 확인 2026-11-22).
- 통과 기준:
  - DSR ≥ 0.95 — **학습 구간** 시행 풀에서(고른 곳에서 다중검정 보정. 확인 구간 풀은 후보 수뿐이라 보정이 거의 없다)
  - 확인 구간: KOSPI200 대비 초과수익 > 0
  - 확인 구간: Sharpe ≥ 학습 구간 Sharpe 의 1/2
  - 확인 구간: MDD ≤ 같은 기간 KOSPI200 MDD
- 통과 후보가 여럿이면 회전율 낮은 쪽. 없으면 모의로 가지 않고 가설 단계로 돌아간다(결과를 보고 가설을 끼워 맞추지 않는다).

### 4. 모의투자 (qf-paper 스택)

- 기동은 사용자 확인 후. 최소 3회 리밸런싱(약 3개월).
- live_gate 체결 정합 표본(n ≥ 30) 충족 확인.
- 같은 기간 백테스트를 다시 돌려 모의 성과와 비교(tracking).
- **실패 기준(하나라도 해당하면 실전 불가):** 모의 수익률이 백테스트 예상 범위를 크게 벗어남 /
  모의 MDD 가 백테스트 최악치의 1.5배 초과.

## 산출물 위치

- 이 설계 문서: 저장소(커밋).
- 리서치 노트·가설·시행 기록·결과: 저장소 루트 `research/`(gitignore 추가) — 공개 저장소라 커밋 금지.

## 빌더에게 맡기는 것

조사 출처 선정, 가설별 구체 가중치·변형, 유니버스 소스 선택, 공통값의 정확한 수치(근거 기록 조건).

## 결정 기록 (빌더 판단 — 사용자 확인 필요)

- 시행 총량 ≤ 15회, 통과 기준 4개 수치, 학습/확인 구간 경계
- 모의 실패 기준(사용자가 기준을 주지 않아 제안값)
- 리서치 산출물을 gitignore 된 `research/` 에 두기
