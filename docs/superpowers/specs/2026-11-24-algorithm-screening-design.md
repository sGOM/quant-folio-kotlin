# 논문 알고리즘 선별 — algorithm 폴더 시험 후 통과분만 Kotlin 적용

작성 2026-11-24. 실수치·결과는 이 문서에 쓰지 않는다(공개 저장소). 결과는 `research/`(git 무시)와 algorithm 폴더에 둔다.

## 왜

퀀트 논문에서 고른 알고리즘 5개가 이 프로젝트의 팩터 리밸런싱 전략에 실제로 도움이 되는지 확인하고,
도움이 되는 것만 Kotlin 백테스트·엔진에 넣는다. 사용자 요청: "한 번으로 끝내지 말고 여러 방식으로 시험".
논문 선정 근거는 이 대화의 조사(Novy-Marx & Velikov 2016, Novy-Marx 2013, Bali·Cakici·Whitelaw 2011,
한국 단기반전 연구, Bailey 외 2017 PBO)다.

## 목표 / 비목표 / 반목표

- **목표:** ① algorithm 폴더에 Python 으로 구현·시험 ② 합격 규칙을 통과한 것만 Kotlin 에 기본값이 꺼진 config 옵션으로 넣는다.
- **비목표:** 확인 구간 사용, 고정된 T1~T12(전략 37) 변경, ML 모델, 전략에 옵션을 켜서 운영하는 것(다음 라운드 가설에서 결정),
  `FactorScores` momentum 의 `mom_1m` 양(+) 방향 수정(원본 보존 — `research/notes.md` 에 기록만).
- **반목표(기술적으로 돌아가도 실패):** 미래참조 / 결측을 0 으로 채움 / 결과를 본 뒤 기준·파라미터 변경 /
  확인 구간(2023-01~2026-10) 데이터를 판정에 사용 / 시행을 기록하지 않음.

## 기준 전략 (Python)

연구 공통값(`research/hypotheses.md`)과 같게:
유니버스 = 결정일 **직전 거래일** KOSPI 보통주 시총 상위 100(`KOSPI_MCAP`), 월간(월 첫 거래일 결정, `next_close` 체결),
`top_n` 20, 동일가중, `drift_band_pct` 0.02, 정수주, 기본 비용 = 수수료 0.015% + 매도세 0.20% + 슬리피지 10bp, 자본 3,000만 원.
점수 = `FactorScores.compute` 와 같은 정의(윈저라이즈 z, 결측은 해당 항목 제외 후 평균, 가중합).
- lowvol = mean(z(−vol_ann), z(mdd_252)) — `PortfolioBacktest.factorFrameOf`·`MetricsCommon` 정의 그대로.
- quality = mean(z(roe), z(−debt_ratio), z(fcf>0), z(f_score)) — DART 연간. 사용 연도는 Kotlin 과 같은
  `DartMetrics.announcementLaggedYear`(4월부터 직전 연도) 규칙(접수일이 아니다 — 원본 보존). 연결 우선·별도 폴백.

기준 전략 세 개(시험 항목 6): **H1 기본**(lowvol .5 + quality .5, 주 기준), lowvol 단독, quality 단독.

### 교정 (시험 전에 먼저)

H1 기본을 같은 설정·학습 구간으로 Kotlin 백테스트에서도 돌려 Python 과 비교한다.
**전략 37 이 아닌 별도 전략**에서 실행한다(DSR 은 strategy_id 단위로 시행을 세므로 37 의 시행 수를 오염시키지 않는다).
새 전략은 만들기만 하고 시작하지 않는다. 웹 API 로그인이 필요하다(비밀번호는 그때 사용자에게 받는다).
비교: 월간 수익률 상관, 연환산 Sharpe 차이, 리밸런싱별 보유 종목 겹침. 허용 기준은 첫 비교 결과를 보기 전에 정한다:
월 수익률 상관 ≥ 0.95, 보유 종목 평균 겹침 ≥ 80%. 미달이면 원인(정수주·드리프트 밴드·DART 추출 차이)을 찾아 맞춘 뒤 진행한다 —
**교정이 통과하기 전에는 변형 시험을 돌리지 않는다.** DART 지표는 Kotlin `DartMetrics` 추출 규칙과 같아야 한다(이식이든 Kotlin 에서 내보내기든 빌더 판단, 표본 종목으로 값 대조 필수).

## 단계 (DART 미적재 때문에, 2026-11-24 사용자 승인)

- **1단계(지금):** 가격만 쓰는 부분. 기준 전략 = lowvol 단독(+ 실제 KOSPI100 유니버스 변형). lowvol 단독으로 교정,
  A1·A3·A4·A5 전 시험 항목, PBO 도구 검증과 lowvol 기준 PBO. 결과는 **잠정** — 합격 판정은 하지 않는다.
- **2단계(DART 백필 완료 후):** H1·quality 단독 기준 전략과 H1 교정, A2 포함 전 알고리즘을 H1 기준(주 기준)으로 다시 시험하고
  항목 6 을 4개 구성 전부로 채워 **최종 판정**. PBO 최종값은 H1 기준 선별. Kotlin 적용은 최종 판정 뒤.
- DART 백필은 2026-11-24 수동 시작(`qf-paper-dart-backfill`, 일 예산 10,000). 완료 확인 = 학습 구간 결정일마다 상위 100 중
  quality 입력 커버리지 ≥ 50%(Kotlin `FactorCoverage.MIN` 과 같은 기준).

## 시험할 알고리즘과 변형

신호형 팩터는 모두 **별도 카테고리**로 넣는다(Kotlin 적용 형태와 같게). 주 변형 가중치 .2, 기존 가중치는 비례 축소(H1: lowvol .4 + quality .4 + 신규 .2).

| # | 알고리즘 | 정의 | 주 변형 | 이웃 변형(항목 4) |
|---|---|---|---|---|
| A1 | 순위 버퍼 (Novy-Marx & Velikov 2016) | 신규 편입은 순위 ≤ 20, 보유 종목은 순위 ≤ 20+k 면 유지, 빈자리는 상위부터 채움 | k=10(30위) | k=5, 20 |
| A2 | GP/A (Novy-Marx 2013) | 매출총이익 / 자산총계, DART 연간·`rcept_dt` 기준. 매출총이익 없는 회사(금융 등)는 null | 가중 .2 | .1, .3 |
| A3 | MAX (Bali 외 2011) | 직전 21거래일 일간 수익률 최댓값, **낮을수록** 좋음 | 가중 .2 | .1, .3 |
| A4 | 단기 반전 | 직전 21거래일 수익률, **낮을수록** 좋음 | 가중 .2 | .1, .3 |
| A5 | A4 + A1 | 반전의 회전율을 버퍼로 상쇄(논문 근거: 고회전 전략은 비용에 약함) | 가중 .2, k=10 | — |
| P | PBO / CSCV (Bailey 외 2017) | 성과가 아니라 **도구**. 아래 검증 | — | — |

## 시험 항목 (모두 학습 구간)

차이(Δ)는 "변형 − 같은 기준 전략", Sharpe 는 비용 차감 연환산.

1. **전체 구간:** 기본 비용에서 ΔSharpe, 회전율, MDD.
2. **하위 구간:** 2017-06~2019-12, 2020-01~2022-12 각각 ΔSharpe.
3. **블록 부트스트랩:** 월 수익률 3개월 블록, 10,000회, P(ΔSharpe > 0).
4. **파라미터 견고성:** 이웃 변형들의 ΔSharpe.
5. **비용 민감도:** 저비용(수수료+세금만) / 기본 / 고비용(슬리피지 30bp).
6. **기준 전략·유니버스:** H1 기본, lowvol 단독, quality 단독(A2 는 quality 단독에 이미 수익성이 있으므로 그대로 적용), 실제 KOSPI100 구성종목 유니버스(H1 기본).
7. **팩터 IC (A2~A4):** 월별 Spearman IC(신호 vs 다음 달 수익률), 평균과 3개월 블록 부트스트랩 95% CI.
8. **위약 대조:**
   - 신호형(A2~A5): 매월 신호를 종목 간 무작위로 섞은 변형 200회 → 실제 ΔSharpe 가 위약 분포 95 백분위 초과.
   - 버퍼(A1): 신호와 무관한 비용 절감이므로 대신 **비용 귀속 검사** — 저비용→기본→고비용으로 갈수록 ΔSharpe 가 커지고,
     저비용에서 ΔSharpe 가 −0.1 보다 나쁘지 않아야 한다(개선이 비용 절감에서 온다는 확인).
9. **PBO:** H1 기본 위의 선별 전체(기준 전략 + A1~A5 주 변형·이웃 변형, 기본 비용, 월 수익률 행렬)에 CSCV, 블록 S=8(조합 70개). 선별 단위 지표다.

## 합격 규칙 (결과 보기 전에 고정)

각 알고리즘(A1~A5)마다:

- **필수 (모두):**
  - 항목 1 ΔSharpe > 0
  - 항목 8 통과
  - 항목 9 PBO < 0.5 (실패하면 **전부 불합격**)
  - 신호형(A2~A4)은 항목 7: IC 부호가 논문 방향(A2 양, A3·A4 음)이고 95% CI 가 0 을 포함하지 않음. A5 는 A4 의 항목 7 결과를 따른다
- **견고성 (과반):** 아래 5개 중 3개 이상
  - 항목 2: 두 하위 구간 모두 Δ > 0
  - 항목 3: P ≥ 0.8
  - 항목 4: 이웃 변형 전부 Δ > 0
  - 항목 5: 기본·고비용 모두 Δ > 0 (A1 은 고비용 Δ > 기본 Δ)
  - 항목 6: 4개 중 3개 이상 Δ > 0

A5 는 A4 와 A1 이 각각 합격하지 않아도 독립 판정하되, Kotlin 적용 시 A1·A4 옵션의 조합으로만 구현한다(별도 코드 없음).

**PBO 도구(P) 의 합격:** 합성 데이터 검증 — ① 순수 잡음 전략 N개 → PBO 가 0.5 근처(0.35~0.65) ② 진짜 신호 1개를 넣은 경우 → PBO < 0.2.
둘 다 통과하면 Kotlin 에 적용한다(성과 판정 대상 아님).

## 적용 (통과분만)

- Kotlin 옵션은 **기본값이 꺼진** config 필드로 추가한다 — 기존 전략·백테스트 결과가 바뀌지 않는다. 이름은 빌더 판단, 후보:
  `selection.hold_buffer`(A1, int, null=끔), `factor_weights.profitability`(A2)·`lottery`(A3)·`reversal`(A4)(기본 0).
- 새 카테고리 가중치 > 0 이면 기존 `FactorCoverage` 관문을 그대로 적용(입력 컬럼 = 해당 신호).
- **입력은 두 곳에 넣는다:** 백테스트 `PortfolioBacktest.factorFrameOf`/`fundamentalsProvider` 와 실매매 `UniverseScores`. 한쪽만 넣으면 백테스트와 실매매가 갈린다.
  버퍼는 현재 보유 종목이 필요하다 — 백테스트 장부와 엔진 `RebalanceRunner` 포지션 양쪽에서 넘긴다.
- **정답지:** algorithm 폴더 Python 구현으로 **합성 입력**의 정답 JSON 을 만들어 `backend/core/src/test/resources/oracle/` 에 둔다(원본 Python 이 아니라 이 구현이 출처임을 파일·테스트에 명시). 실데이터 결과는 커밋 금지.
- PBO 는 `DeflatedSharpe` 옆의 순수 계산으로 둔다. 노출 방식(API 응답 필드 등)은 빌더 판단.
- **Kotlin 재현 확인:** 적용한 옵션을 켠 Kotlin 백테스트(교정용 별도 전략, 학습 구간)의 ΔSharpe 부호가 Python 과 같아야 한다. 다르면 적용을 멈추고 원인을 보고한다.
- 문서: `strategy-config.md` 등 낡는 서술은 단계 종료 `doc-check` 에서 갱신.
