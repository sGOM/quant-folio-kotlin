**Goal:** 4단계 전체가 올라설 기반 — 원본 Python 을 돌려 정답지를 만드는 하네스, pandas 의미를 재현하는 `Series`/`Panel`, 공용 수치 유틸.

**Architecture:** `tools/oracle/` 의 Python 스크립트를 원본 이미지(`quantfolio-web`) 안에서 기준 커밋 소스를 마운트해 실행하고, 결과 JSON 을

Kotlin 쪽은 `core/quant/` 에 날짜 인덱스 `Series`(DoubleArray, 결측 NaN)와 날짜×종목 `Panel`(`upTo(d)` 뷰로 미래참조를 구조적으로 차단).

**Spec:** 설계 §8 (정답지·pandas 체크리스트)

## Global Constraints

- 정답지 입력은 스크립트 안에서 `numpy.random.RandomState(시드)` 로 만들고 **입력과 출력을 함께** JSON 에 담는다(Kotlin 이 난수를 재현하지 않는다). NaN/±Inf 는 문자열 `"NaN"`/`"Infinity"`/`"-Infinity"`.
- 허용 오차: 상대 1e-9(누적 연산은 1e-6, 테스트에 근거 주석). 정수·순위·선택 결과는 완전 일치.
- pandas 2.2.3 의미를 따른다: rolling `min_periods` 기본=window·NaN 은 개수에서 제외, std `ddof=1`, ewm `adjust=True`·`ignore_na=False`, `pct_change` 기본 `fill_method='pad'`, sum skipna(전부 NaN → 0), mean 전부 NaN → NaN.
- 반올림은 half-even(`Math.rint`). 정렬은 안정 정렬을 쓰되 pandas 와 다른 동점 처리는 함수별로 명시.
- 정답지에 실데이터·키를 넣지 않는다(공개 저장소).

## Review Focus

1. **창 안에 NaN 이 섞인 rolling** — pandas 는 개수에서 빼고 min_periods 로 판정. → Task 2 정답지 케이스.
2. **ewm 의 선행 NaN·중간 NaN** — 가중치 재정규화. → Task 2.
3. **pct_change 의 NaN 전방채움** — 2.2.3 기본 pad. → Task 2.
4. **`Panel.upTo(d)` 이후 데이터 접근** — 구조적으로 불가해야 한다. → Task 3 `upToHidesFuture`.
5. **MDD·연환산 변동성 경계(행 < 2, < 20)** — null. → Task 4.
