# 9단계 컷오버 Runbook

**전제:** 8단계 완료, CI 녹색. 소유자가 실행 시점을 정한다(원본 매매가 멈춘다). 모의투자라 정지 허용(설계 §1).
**되돌리기:** 10단계까지는 언제든 Kotlin 스택을 내리고 원본을 다시 올리면 된다 — 단 Flyway baseline 이후 원본은 `flyway_schema_history` 테이블을 무시하므로 영향 없음.

## 절차 (원본 저장소 = `$ORIG`, 이 저장소 = `$KT`)
1. **매매 중지 확인:** 미체결 주문이 없을 때(장 마감 후 권장). `$ORIG` 에서 `docker compose exec db psql -U quant -c "select count(*) from orders where status in ('pending','submitted','partial')"` → 0 이 아니면 정합 후 재확인.
2. **백업:** `docker compose -f $ORIG/docker-compose.yml exec -T db pg_dump -U quant quant | gzip > backup_precutover_$(date +%Y%m%d).sql.gz` — 파일 크기·`zcat | grep -c "CREATE TABLE"` 확인. 볼륨 스냅샷도 권장: `docker run --rm -v quantfolio_pgdata:/v -v $PWD:/b alpine tar czf /b/pgdata.tgz -C /v .`
3. **시크릿 이전:** `$ORIG/secrets/*.txt` → `$KT/secrets/`(13개, 특히 `credential_enc_key.txt` 동일해야 DB 자격증명 복호화). `.env` 는 `$KT/.env.example` 기준으로 값만 옮긴다(`KIS_ACCOUNT_NO`·`KIS_HTS_ID`·`KIS_ENV`·쿠키·포트).
4. **원본 앱 중지(DB·Redis 유지):** `cd $ORIG && docker compose stop web engine worker frontend proxy`.
5. **Kotlin 기동:** `cd $KT && docker compose up -d --build` — 같은 프로젝트명 `quantfolio` 라 기존 `db`·`redis` 컨테이너·`pgdata` 볼륨을 이어받는다. web 이 Flyway baseline(V1) 후 healthy.
6. **스모크:** `curl -s localhost:8080/health` → `"status":"ok"`, `cd frontend && E2E_BASE_URL=http://localhost:8080 npm run test:e2e`, 기존 계정 로그인·전략 목록·포지션 화면 확인.
7. **엔진 확인:** `docker compose logs engine | grep "운용 중 전략 복구"`, `redis-cli smembers engine:active_strategies`, heartbeat. 장중 첫 틱의 주문·체결 정합을 지켜본다.
8. **관찰 1주:** 알림(critical)·`runner_failures`·체결 정합 리포트·야간 백업(`/backups`)·뉴스/스냅샷 배치.
9. **정리:** 원본 저장소 archive. `alembic_version` 테이블은 남겨 둔다(설계 §7).
