# 1단계 골격 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 이후 모든 단계가 올라설 Kotlin 백엔드 골격 — 빌드·DB 스키마·엔티티·공용 상수·CI·Claude 문서 체계.

**Architecture:** `backend/` 아래 Gradle 멀티모듈(core 라이브러리 + web/engine/worker 3개 Boot 앱). 스키마는 원본 Alembic 0017 을
재생한 DB 의 public 스키마 덤프를 Flyway V1 으로 고정하고, JPA 엔티티는 `ddl-auto=validate` 로 V1 과 일치를 강제한다.

**Tech Stack:** Java 25, Kotlin 2.3.21, Spring Boot 4.1.1, Gradle 9.8.1(wrapper), Flyway, Spring Data JPA, Spring Data Redis, Testcontainers(`timescale/timescaledb:latest-pg16`, `redis:7-alpine`), Node(훅·린트 스크립트).

**Spec:** `docs/superpowers/specs/2026-10-19-kotlin-migration-design.md`

## Global Constraints

- 패키지 루트 `com.quantfolio`. 모듈 경로 `backend/core`, `backend/web`, `backend/engine`, `backend/worker`.
- Redis 키·채널 문자열은 원본 `app/core/channels.py` 와 **문자열 동일**.
- 거래일은 `Asia/Seoul` 기준 단일 헬퍼로만 얻는다.
- 시크릿은 `spring.config.import=optional:configtree:/run/secrets/`.
- Flyway `baselineOnMigrate=true`, `baselineVersion=1`. `alembic_version` 테이블은 건드리지 않는다.
- JPA `ddl-auto=validate`. 엔티티가 스키마를 바꾸지 않는다.
- CLAUDE.md ≤ 80줄, `.claude/rules/*.md` 는 `paths` frontmatter 필수·≤ 150줄.
- 원본 기준 커밋 `8a563702`.

## Review Focus

1. **기존 운영 DB 에 Flyway 첫 기동** — 테이블은 있고 `flyway_schema_history` 가 없는 DB. V1 을 재실행하면 안 되고 baseline 만 기록해야 한다. → Task 2 테스트.
2. **hypertable 이 빈 DB 에서도 생성되는가** — V1 에 `create_hypertable` 이 빠지면 CI DB 와 운영 DB 가 갈린다. → Task 2 테스트.
3. **JSONB·NUMERIC·timestamptz 매핑** — 잘못 매핑하면 validate 는 통과해도 값이 깨진다(NUMERIC→Double 정밀도). → Task 3 왕복 테스트.
4. **UTC 컨테이너에서 KST 자정 직후** — 00:30 KST(= 전날 15:30 UTC)에 거래일이 KST 날짜로 나와야 한다. → Task 4 테스트.
5. **md 린트가 낡은 `paths` 를 잡는가** — 어떤 파일에도 매칭 안 되는 glob 이 있으면 실패해야 한다. → Task 6 테스트.

### Task 3: 운영·스토어 JPA 엔티티

**Files:**
- Create: `backend/core/src/main/kotlin/com/quantfolio/domain/<영역>/*.kt` — 엔티티 + `JpaRepository`
  - `user/User`, `strategy/Strategy`, `strategy/StrategyLike`, `backtest/Backtest`, `trading/Order`, `trading/Execution`, `trading/Position`, `trading/RiskLimit`, `alert/Alert`, `news/NewsArticle`, `news/NewsArticleSymbol`, `market/SectorMapSnapshot`, `market/KisStockMasterSnapshot`
- Test: `backend/core/src/test/kotlin/com/quantfolio/domain/EntityMappingTest.kt`

시장데이터 저장소 테이블(price_ticks·stock_daily_snapshots·stock_period_stats·index_*·dart_financials·external_fetches)은 **JPA 엔티티를 만들지 않는다** — 3단계에서 JdbcTemplate 리포지토리로 다룬다(설계 §4.1).

컬럼·타입·nullable·기본값은 원본 `backend/app/models/models.py` 와 V1 을 따른다. 매핑 규칙: NUMERIC → `BigDecimal`, timestamptz → `Instant`(`OffsetDateTime` 아님), date → `LocalDate`, JSONB → `@JdbcTypeCode(SqlTypes.JSON)` + `Map<String, Any?>`(구체 타입은 4단계에서), PK 는 `IDENTITY`.

- [ ] **Step 1: 실패 테스트**
  - `schemaValidates`: `ddl-auto=validate` 로 컨텍스트 로드 성공.
  - `roundTripsTypes`: User → Strategy(config = `{"a":1,"b":[1.5,null],"c":{"d":"한글"}}`) 저장 후 재조회 시 config 동일; Position.avgPrice `BigDecimal("12345.6789")` 정확히 보존; Order.createdAt Instant 보존(마이크로초 절삭 허용).
