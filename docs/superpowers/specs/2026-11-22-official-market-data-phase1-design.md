# 공식 경로 시장데이터 1단계 — 설계

## 의도

2026-11-22 전략 리서치 백테스트 2회가 KRX Data Marketplace(MDC)를 대량 조회해 **IP 1일 차단**을 받았다
(약관 제10조 2호: 자동 수집 금지). 같은 경로에 실매매(리밸런싱의 구성종목·시총·업종)와 worker 정기 적재도 기대고 있다.
또 백테스트가 실행 중 외부를 즉석 조회하면서 일부 실패를 경고 없이 삼켜 결과가 무효가 됐다.

사용자 목표: **연구·매매가 외부 사정으로 멈추지 않게, 공식 경로만 쓴다.** 최종 형태는 B(MDC·네이버 수집 전면 제거)이고
두 단계로 나눈다(사용자 결정 2026-11-22).

- **1단계(이 문서):** 전략 경로 — 백테스트, 실매매 리밸런싱, 국면 필터, 급락 감지(panic), 거래일 달력, worker 정기 적재, 종목 목록.
- **2단계(별도 설계):** 화면 지표·스크리너·추천을 1단계 데이터로 이전, flow 팩터·투자자별 순매수 화면 삭제, MDC·네이버 코드 삭제.

1단계가 끝나면 `2026-11-22-initial-factor-strategy` 리서치를 T1 부터 재개한다.

## 목표 / 비목표 / 반목표

- **목표**
  - 1단계 범위 코드가 KRX MDC·네이버 차트를 호출하지 않는다.
  - worker 가 공식 소스에서 적재한다: 한도 준수, 중단 후 이어받기, 실패는 기존 알림 경로로.
  - 백테스트·엔진은 **로컬 DB 만** 읽는다. 결측이면 "무엇이·어느 기간이 비었는지"를 담은 예외로 즉시 실패한다.
  - 새 유니버스 소스: **KOSPI 보통주 시가총액 상위 N**(시점별).
  - 밸류 지표(PER·PBR·배당수익률)를 DART 재무·배당 + 시가총액으로 직접 계산.
- **비목표:** 화면 지표·스크리너·추천 이전(2단계), flow 대체(공식 소스 없음, 쓰는 전략 0개 — 2026-11-22 DB 확인),
  실시간 시세·주문 경로 변경(KIS 유지).
- **반목표**
  - 조용한 저하: 결측을 중립·0 으로 메우고 "성공".
  - 생존 편향: 상장폐지 종목이 과거 데이터에서 빠지는 것.
  - 미래참조: 유니버스·밸류가 결정일 d 이후 데이터를 보는 것.
  - 원천값 유실: 원주가·전일대비를 버리고 가공값만 저장해 재계산이 불가능해지는 것.

## 제약

- **KRX Open API** — 사용자 준비 필요.
  - 인증키(1년 만료) 발급 후 서비스별 이용 신청·승인을 받는다.
    필요 서비스: 유가증권·코스닥 일별매매정보, 유가증권·코스닥 종목기본정보, KRX·KOSPI·KOSDAQ 지수 일별시세.
  - 키는 `secrets/krx_openapi_key.txt` 에 사용자가 만든다(시크릿 편집은 훅이 막는다).
  - 2010-01-04 부터 제공한다.
  - 일 호출 한도는 서드파티 문서상 10,000 — **미확인**, 승인 후 실측한다.
  - 공개 시점(T+1 몇 시)도 실측한다.
- **OpenDART:** 일 약 20,000 호출(020 = 한도 초과). 이미 키 있음.
- **원본 동작 보존 원칙의 의도적 예외:** 소스 교체와 "결측이면 실패"는 원본과 다르다. 원본 스택은 2026-11-17 퇴역했다.
  변경점은 `docs/migration-notes.md` 에 기록한다.
- 기존 전역 규칙을 따른다: KST 날짜(`MarketClock`), 결측은 null, 실패 종류 구분, 미래참조 금지, 실데이터 정답지 커밋 금지(공개 저장소).

## 접근법

| 결정 | 고려한 안 | 선택 |
|---|---|---|
| 범위 | A 전략 경로만 / **B 전면 제거를 2단계로** | B·2단계 — 약관 위험 0, 화면·전략 숫자 단일 출처. 잃는 것은 flow 화면뿐 |
| 과거 가격 | **1. Open API 단일**(원주가 + 전일대비로 수정주가 계산) / 2. KIS 기간별시세(수정주가) + Open API 시총 / 3. 네이버 유지 | 1 — 상폐 종목 포함(생존 편향 없음), 시장당 하루 1호출, 유니버스와 같은 출처. 2는 상폐 종목 누락 가능, 3은 비공식 |
| 유니버스 | **(a) 시총 상위 N 규칙** / (b) 사람이 화면 다운로드(연 2회) | (a) — 사람 손 불필요, 백테스트·실매매 같은 규칙. 실제 지수와 몇 종목 차이 감수 |

## 설계 (사용자 결정 반영)

### 소스 매핑 (1단계 소비처)

| 소비처 | 지금(MDC·네이버) | 1단계 |
|---|---|---|
| 종목 일봉(`price_ticks`) | 네이버 차트 | Open API 일별매매정보 → 수정주가 계산 |
| 시가총액·상장주식수 | MDC | Open API 일별매매정보 |
| 지수 일봉(국면 필터·벤치마크·panic) | MDC | Open API 지수 일별시세 |
| 구성종목(PIT) | MDC + `index_constituents` | 신규 소스 "시총 상위 N" |
| 업종(`neutralize: sector`·`max_sector_pct`) | MDC 업종 | KIS 종목마스터 업종 코드(이미 스냅샷 적재 중) — **분류 체계가 달라** 업종 중립화 결과가 바뀐다 |
| PER·PBR·DIV | MDC | 직접 계산(아래) |
| 재무(quality·growth·pead) | OpenDART 즉석 | OpenDART, worker 백필 후 로컬 |
| panic(전 종목 등락·신저가 비율) | MDC | 로컬 일별매매정보 |
| 거래일 달력 | MDC `nearestBusinessDay` | 과거: 로컬 지수 일봉의 날짜. 오늘·미래: KIS 국내휴장일조회 |
| 종목 목록(`SymbolCatalog`) | MDC + FDR | Open API 종목기본정보 + KIS 마스터 |

### 수정주가

- 원천: 일별매매정보의 종가 `TDD_CLSPRC`, 전일대비 `CMPPREVDD_PRC`.
- KRX 전일대비는 권리락·분할을 반영한 **기준가** 대비 값이다 → 일수익률 `r_t = 종가_t / (종가_t − 전일대비_t) − 1`.
- 원천값(원주가·전일대비·시가/고가/저가·거래량·시총·상장주식수)은 그대로 저장한다.
- 수정주가는 최신일 기준 역산(back-adjust)한다. 네이버 수정주가·원본과 같은 의미다(과거 가격이 이후 기업행위로 바뀌는 것은 기존과 같은 알려진 예외).
- `price_ticks` 를 읽는 쪽(백테스트·엔진·분석 화면)이 받는 의미(수정 일봉)는 유지한다.
- **검증:** 삼성전자 액면분할 50:1(2018-05-04) 전후 수정 수익률이 −98% 가 아니라 실제 등락이어야 한다. 2010 이후 상폐 종목 1개가 상폐 전 날짜에 존재해야 한다.

### 유니버스: 시총 상위 N

- 리밸런싱일 d 의 후보 = d **직전 거래일** KOSPI 종목 중 **보통주**(종목기본정보의 주권 종류), 시가총액 상위 N.
- 스키마: `universe_rule.source` 에 새 값(이름은 빌더)을 추가하고 N 은 `pick` 을 쓴다.
- `dynamicUniverse` 의 모멘텀 절단은 이 소스에서도 그대로 적용된다(pick ≥ N 이면 사실상 무효 — 기존 동작).
- 기존 소스(KOSPI200·KOSPI100·KRX300)는 1단계에서 `index_constituents` **로컬 캐시만** 읽는다. 없으면 명시적 실패. 존폐는 2단계에서 정한다.
- 미래참조 수용 테스트: `PortfolioLookaheadTest` 와 같은 방식으로 cut 이후 시총 교란 → cut 까지 유니버스·결과 동일.

### 밸류 지표 계산 (시점 d)

- PER = 시가총액_d / 지배주주 당기순이익, PBR = 시가총액_d / 지배주주 자본, DIV = 주당 현금배당 / 종가_d.
- 재무·배당은 **접수일 ≤ d** 인 최신 사업보고서(annual) 기준 — KRX 가 공시하던 PER(직전 사업연도 EPS)과 같은 성격.
- 적자·자본잠식이면 PER·PBR 은 null(0 아님).
- DART 정정공시 미래참조는 기존 예외(`migration-notes` #10~12)를 그대로 따른다.

### 배당 반영 (사용자 결정 2026-11-22)

현재 백테스트는 가격수익률만 센다 → 고배당 성향 전략이 체계적으로 불리하다. 1단계에서 현금배당을 넣는다.

- **데이터:** 종목별 배당기준일·주당 현금배당금(보통주). 출처는 스파이크에서 확정한다.
  - 후보: [공공데이터포털 금융위원회 주식배당정보](https://www.data.go.kr/data/15059609/openapi.do)·주식권리일정정보,
    DART 배당 사항(연간 DPS).
  - 공공데이터포털이면 서비스키가 필요하다(사용자 준비, `secrets/` 에 둔다). 2010 이후 커버리지를 실측한다.
- **수정주가와의 관계:** KRX 기준가는 현금배당에는 조정되지 않는다(주식배당·권리락만 조정 — 스파이크에서 고배당 종목의 배당락일 전일대비로 확인).
  따라서 전일대비 기반 수익률에는 현금배당이 없고, 백테스트가 따로 더한다(이중 계산 없음).
- **백테스트 의미:** 배당락일(배당기준일 직전 거래일) 종가 시점에 보유 주식 수 × 주당배당금을 현금으로 적립한다.
  세금은 config 에 배당세율 필드를 추가하고 기본값은 15.4%다. 지급일(국내는 1~4개월 뒤)이 아니라 배당락일 적립은 의도한 단순화다 — 문서에 적는다.
- **미래참조:** 배당락일 d 의 적립은 d 이전에 공시된 배당 결정만 쓴다. 배당 결정 공시일을 알 수 없는 출처면 배당기준일을 공시 시점의 상한으로 본다.
  `PortfolioLookaheadTest` 를 다시 초록으로 만들고, cut 이후 배당 교란 → cut 까지 결과 동일 테스트를 추가한다.
- **벤치마크:** KOSPI200 가격지수와 비교하면 전략만 배당을 받는 셈이다.
  Open API 에 KOSPI200 총수익지수(TR)가 있으면 벤치마크 비교에 쓴다. 없으면 가격지수를 쓰고 결과에 "벤치마크는 배당 제외"를 표기한다(스파이크에서 확인).
- 실매매는 실제 배당이 계좌 현금으로 들어오므로 엔진 변경은 없다. 모의 관찰의 백테스트 비교(tracking)는 배당 포함 백테스트와 비교한다.

### 적재 (worker)

- **백필 작업:** 2010-01-04 부터 오늘까지.
  - 거래일마다 일별매매정보(KOSPI·KOSDAQ)·종목기본정보·지수 일별시세를 받는다.
  - 기존 `FetchLedger` 로 이어받는다. 일 한도의 일정 비율 안에서 멈추고 다음 날 재개한다.
- **DART 백필:** KOSPI 보통주 전체 2015~, 백테스트 팩터가 요구하는 보고서 종류. 한도 인지, 이어받기.
- **일일 작업:** 기존 `ingestDailySnapshots`·`ingestDailyOhlcv`·`snapshotSectorMap` 의 MDC·네이버 호출을 공식 소스로 교체한다. 실행 시각은 Open API 공개 시점 실측 후 정한다.
- 실패는 기존 `withOutageAlert` 알림. 0행·전부 null 컬럼은 확정하지 않는다(기존 `StoreCache` 규칙).

### 로컬 전용 읽기

- 백테스트·엔진의 시장데이터 조회는 외부를 호출하지 않는다.
- 요청 범위에 결측이 있으면 새 예외(이름은 빌더, `DataSourceError` 와 구분되는 "미적재")를 던진다.
  예외에는 데이터 종류·종목·빠진 날짜 구간을 담는다. API 는 이를 4xx/5xx 중 무엇으로 낼지 빌더가 정한다(문구는 원인 그대로).
- 팩터 커버리지: 가중치가 걸린 팩터 입력이 리밸런싱 시점마다 일정 비율 미만이면 실패.
  비율은 빌더가 근거와 함께 정한다. 마지막 날만 보던 `factorCoverageWarnings` 의 사각을 메운다.

## 설계자 판단 (사용자 확인 대상)

- **실매매 리밸런싱 시점에 전 거래일 데이터가 미적재면 그날 리밸런싱을 하지 않고 critical 알림**(fail-closed).
  추정값으로 주문하지 않는다.
- 기존 `price_ticks`(네이버)는 Open API 백필 결과를 검증(분할일·상폐 종목·임의 종목 수익률 대조)한 뒤 교체한다. 교체 전 덤프를 남긴다.
- 백필 범위는 KOSDAQ 포함 — panic·국면 필터의 KOSDAQ 옵션과 2단계 화면 이전에 필요하고, 호출 수는 시장당 하루 1회다.
- 리서치 가설 파일에는 유니버스 소스 변경(KOSPI100 → 시총 상위 100)을 날짜·사유와 함께 추가한다(고정 후 추가만 규칙).

## 빌더에게 맡기는 것

테이블 설계(기존 `stock_daily_snapshots` 확장 vs 신규 — 원천값 보존 조건), 클라이언트 구조, 새 소스·예외 이름,
일일 작업 시각, 백필 속도, KIS 휴장일 API 연동 위치, 커버리지 임계값.
